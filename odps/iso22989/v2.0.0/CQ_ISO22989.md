# Competency Questions: ISO/IEC 22989 Pattern (AI Concepts)

Ontology design pattern for the terminology of artificial intelligence.

Normative basis: ISO/IEC 22989:2022, Information technology, Artificial
intelligence, Artificial intelligence concepts and terminology.

IRI: `https://w3id.org/aias/odp/iso22989/`
Named individuals: `https://w3id.org/aias/odp/iso22989/instances/`

Every question is answered from the A-box of a modelled case. The pattern ships
named individuals for the qualities of clause 3.5 and for the system designs,
and a case uses them as it needs them. Those individuals are A-box themselves,
but listing them is not a competency question: the answer would be the same
whichever case is loaded.

One question, 26, holds such a catalogue against a case and reports per entry
whether the case states a value for it. Its query declares that, since the rows
there are the scale rather than the finding.

Clause 3 of the standard holds 115 entries and the pattern takes up 47 of them.
`REFERENCE.md` lists every entry with the reason it is taken or left out.

The answer column states what a query returns, not how it is computed.

## On question 14

The distinction the pattern is built around, and the reason the three cases
exist.

Entry 3.1.23 defines the model in general and 3.3.7 the machine learning model.
The pattern keeps the second below the first, so a rule-based system can be
recorded as having a model without pretending it was trained. A pattern
equating the two would either force a training that never happened or leave
such a system without a model at all.

Test case 2 is where it shows: its model answers no in the learned column, and
carries a rule algorithm and no training. Test case 3 carries one of each,
which is what a hybrid system is.

The column is read off the class rather than off the presence of a training, so
a model recorded before its training is stated still answers correctly.

## Open points for modelling

1. **Control is defined identically in two standards.** 3.5.5 gives the same
   wording as IEC 60050-351, 351-42-19, and both trace back to the same source.
   The pattern carries its own class and states nothing about the other, since a
   pattern that referenced another namespace would drag it along wherever it is
   used. The alignment relates the two with `owl:equivalentClass`.

   The class sits among the functions, alongside training, inference and the
   rest. Its entry is filed in clause 3.5 with the terms related to
   trustworthiness, but that is a grouping by subject rather than a statement
   about the kind of term: the definition says action, which is what the other
   functions are as well. A system therefore relates to it through
   `hasFunction`, and question 07 returns it like any other activity.

2. **Automation is an adjective in this standard.** 3.1.7 defines automatic,
   automation and automated as pertaining to a process or system functioning
   without human intervention, which is the same wording as IEC 60050-351,
   351-42-30. Both are properties rather than kinds of thing. Where the
   information model of this work carries automating as a function of the life
   cycle, that is a reading of the entry rather than the entry itself, and the
   note on the class says so.

3. **The AI function of clause 8.3 is narrower than the class of that name.**
   The standard uses the term for computing a prediction alone. The pattern
   uses it as a collecting class for the activities of the life cycle, which is
   a construct of this work.

4. **Two model entries, kept apart.** 3.1.23 defines the model in general as a
   representation of a system, entity, phenomenon, process or data. 3.3.7
   defines the machine learning model as a mathematical construct generating an
   inference. A symbolic AI system has a model without it being learned, so the
   pattern keeps the general class above the machine learning one.

5. **The disjointness of the data kinds is asserted, not derived.** The notes to
   3.2.14 and 3.2.15 state that test, training and validation data are disjoint.
   A model that puts one dataset in two of the three is inconsistent, which a
   negative model tests.

6. **Neural networks, language processing and vision are left out entirely.**
   Clauses 3.4, 3.6 and 3.7 name techniques and application fields, both open
   sets. A model using a convolutional network records it as a named individual
   of the model algorithm class, which is how the accompanying text of this work
   describes the extension path.

7. **The qualities carry no scale.** The pattern records that a value belongs to
   a quality, not how the quality is measured. Robustness as a number between
   zero and one is one convention among several, and prescribing it here would
   put a measurement decision into a terminology pattern.
