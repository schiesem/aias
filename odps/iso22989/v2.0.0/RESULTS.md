### CQ 01: Which AI systems exist, and of which components?

each? 3.1.4 defines the AI system as an engineered system generating outputs for a given set of human-defined objectives, 3.1.2 the component as a functional element constructing it. A system without components is not an error. Cases 1 and 2 relate their functions to the system directly, which suffices while there is one of each kind. Case 3 needs the components, since two of them perform the same kind of function differently.

**Query** `tests/queries/cq01_systems_and_components.rq`

```sparql
PREFIX iso:  <https://w3id.org/aias/odp/iso22989#>
PREFIX inst: <https://w3id.org/aias/odp/iso22989/instances#>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
PREFIX owl:  <http://www.w3.org/2002/07/owl#>
SELECT ?system (GROUP_CONCAT(DISTINCT ?c; separator=", ") AS ?components)
WHERE {
  ?system a iso:AISystem .
  OPTIONAL { ?system iso:consistsOf ?component }
  BIND(COALESCE(STR(?component), "") AS ?c)
} GROUP BY ?system ORDER BY ?system
```

**Results**

| Case | system | components |
|---|---|---|
| tc1_subsymbolic | SystemA |  |
| tc2_symbolic | SystemB |  |
| tc3_hybrid | SystemC | ComponentC2 |

**Interpretation.** One system per case. Only case 3 reports components, having two, one per
approach.

Entry 3.1.2 makes the component a functional element that constructs a system,
and a model needs it as soon as one system carries more than one approach: a
learned classifier alongside a rule-based decision would otherwise be
indistinguishable.

### CQ 10: Which functions use no data?

An AI function without data is a function nothing flows through. Clause 5.10 has the activities of the life cycle transform input data into output data, so a function stating none has either not been described or does not belong to that chain. The kind is what tells the two apart. An inference without data is incomplete, since it computes a prediction from something. A control, 3.5.5, may legitimately state none: it acts on a process rather than on a dataset, and the AIAS alignment reaches what it acts on through a relation of its own. OWL cannot require the data under the open world assumption, so this reports where a model has stayed silent rather than where it is wrong.

### CQ 12: Which hyperparameters does an algorithm have, and what were they set to?

Test case 2 uses that: a rule threshold is chosen in advance and steers the behaviour of the procedure, so it is a hyperparameter rather than a model parameter. ### CQ 14: Which models exist, and which of them were learned?

The distinction the pattern is built around. Entry 3.1.23 defines the model in general and 3.3.7 the machine learning model, and the pattern keeps the second below the first rather than treating the two as one. A rule-based system has a model. It was written rather than trained, and a pattern equating model with machine learning model would have no way to say so: it would either force a training that never happened or leave the system without a model at all. Test case 2 is the case that needs it. Its model is a Model and not an MLModel, and the second column reads no. Test case 3 carries both kinds at once, which is what a hybrid system is. Whether a model was learned is read off its class rather than off the presence of a training, so a model recorded before its training is stated still answers correctly.

**Query** `tests/queries/cq14_models_learned_or_not.rq`

```sparql

WHERE {
  ?model a ?modelKind . ?modelKind rdfs:subClassOf* iso:Model .
  FILTER NOT EXISTS { ?model a ?narrower .
                      ?narrower rdfs:subClassOf+ ?modelKind ;
                                rdfs:subClassOf* iso:Model }
  BIND(IF(EXISTS { ?model a ?ml . ?ml rdfs:subClassOf* iso:MLModel },
```
