### CQ 01: Where is the AI trained?

The training is a function like any other, so it reaches its resource through the same assignment that ties a stamping step to a motor. That is what the common function level of the alignment is for. The kind of resource is reported alongside, since the answer to this question is an architectural fact: training in an external cloud means the data leaves the organisation.

**Query** `tests/queries/cq01_where_training_runs.rq`

```sparql

WHERE {
  ?training a ?tk . ?tk rdfs:subClassOf* iso22989:Training .

  ?resource a ?resourceKind . ?resourceKind rdfs:subClassOf* aias:Resource .
```

### CQ 02: What does an inference take in, and what does it produce?

Entry 3.1.17 defines the inference as reasoning that derives results from given data. Both halves are recorded: usesData names what goes in, creates names the prediction that comes out. The task the prediction addresses is reported as well, so the answer runs from the data a model was given to the question it was asked.

```sparql
WHERE {
  ?inference a iso22989:Inference .
```

### CQ 03: What does a training take in, and what does it produce?

The counterpart of question 02, and the asymmetry is the point. A training takes data and produces parameters, not data: determines names the model parameters it fixes, and the model carrying them is reached from the other side through isCreatedBy. A model is therefore not the output of a training in the way a prediction is the output of an inference. It is the thing the parameters end up in.

**Query** `tests/queries/cq03_training_data.rq`

```sparql

SELECT ?training ?input ?inputKind ?parameter ?model
WHERE {
  ?training a ?tk . ?tk rdfs:subClassOf* iso22989:Training .
  OPTIONAL { ?training iso22989:usesData ?input .
             ?input a ?inputKind . ?inputKind rdfs:subClassOf* iso22989:Data .
             FILTER NOT EXISTS { ?input a ?n . ?n rdfs:subClassOf+ ?inputKind } }
  OPTIONAL { ?training iso22989:determines ?parameter }
  OPTIONAL { ?model iso22989:isCreatedBy ?training }
} ORDER BY ?training ?input
```

**Results**

**Interpretation.** Two rows, one per input. The training uses the training dataset and the merged

side.

### CQ 04: Which data is stored, and where?

Two steps. isStoredBy names the storing function, and that function reaches a sink through hasDataSink and a resource through the assignment. The sink says what the data is written to, the resource says which device holds it. Data with no storing at all appears with an empty storing column, which is the answer for anything that only passes through.

**Query** `tests/queries/cq04_data_stored_where.rq`

```sparql
PREFIX aias:     <https://w3id.org/aias#>
PREFIX vdi3682:  <https://w3id.org/aias/odp/vdi3682#>
PREFIX iso22989: <https://w3id.org/aias/odp/iso22989#>
PREFIX rdfs:     <http://www.w3.org/2000/01/rdf-schema#>
SELECT ?data ?dataKind ?storing ?sink ?resource
WHERE {
  ?data a ?dataKind . ?dataKind rdfs:subClassOf* iso22989:Data .
  FILTER NOT EXISTS { ?data a ?n . ?n rdfs:subClassOf+ ?dataKind }
  ?data iso22989:isStoredBy ?storing .
  OPTIONAL { ?storing iso22989:hasDataSink ?sink }
  OPTIONAL { ?storing aias:isAssignedTo/vdi3682:isAssignedTo ?resource }
} ORDER BY ?data
```

**Results**

|---|---|---|---|---|---|
| tc1_stanzprozess | RawMotorData | ProductionData | Speicherung | CloudAlsSenke | ProCube |
| tc1_stanzprozess | RawPositionData | ProductionData | Speicherung | CloudAlsSenke | ProCube |

**Interpretation.** Three datasets are stored, all of them in the cloud through one storing
function: the raw position data, the raw motor data and the merged result.

Two steps lead there. `isStoredBy` names the function, the function names its
sink and the assignment names the device. Sink and device answer different
questions: the sink says what the data is written to, the device says which
machine holds it.

The prepared data does not appear. It passes through the edge device and is
merged rather than stored on its own, which the answer shows by leaving it out.

### CQ 05: Where does a model run?

A model executes an inference, and the inference is assigned to a resource. The model itself is never assigned to anything: it is an artefact, not a function, and what runs is the inference it carries out. That indirection is the answer to the question. Asking where a model runs means asking where its inference runs.

**Query** `tests/queries/cq05_where_model_runs.rq`

```sparql
PREFIX aias:     <https://w3id.org/aias#>
PREFIX vdi3682:  <https://w3id.org/aias/odp/vdi3682#>
PREFIX iso22989: <https://w3id.org/aias/odp/iso22989#>
PREFIX rdfs:     <http://www.w3.org/2000/01/rdf-schema#>
SELECT ?model ?inference ?resource ?resourceKind
WHERE {
  ?model a ?mk . ?mk rdfs:subClassOf* iso22989:Model .
  ?model iso22989:executes ?inference .
  OPTIONAL {
    ?inference aias:isAssignedTo/vdi3682:isAssignedTo ?resource .
    ?resource a ?resourceKind . ?resourceKind rdfs:subClassOf* aias:Resource .
    FILTER NOT EXISTS { ?resource a ?n . ?n rdfs:subClassOf+ ?resourceKind }
  }
} ORDER BY ?model
```

|---|---|---|---|---|

The indirection is the answer rather than an obstacle to it. A model is an

### CQ 06: Which artefact is a model, and which training produced it?

The label of a model instance is the relative path of the file it stands for, models/ProductionNet_v1.onnx in the worked example. That is how the dissertation ties the abstract model to what is actually deployed: a name in the graph is a path in the project. The question therefore asks for the name rather than for a place. A model has no relation to a resource, and adding one would state something the model does not know: where a file lies is a matter for the deployment, not for the description of the system.

### CQ 08: Which functions are assigned to no resource?

A function that nothing carries out is either an unfinished description or a function of the process rather than of the AI. The kind is reported so the two can be told apart. OWL cannot require the assignment under the open world assumption: a function without one is unstated rather than unassigned. The answer therefore reports where a model has stayed silent, and SHACL is where it would become a rule.

### CQ 09: Which data is recorded, and where?

Where data comes from is two steps away: the acquisition names the source it was taken from, and the assignment names the device carrying out that acquisition. Source and device answer different questions. The source says what the data is about, the device says where in the plant it was taken. The two often nearly coincide, but they need not: an acquisition running on an edge device may well read a sensor two levels below. Anchored on the data rather than on the production data. What an acquisition yields is not always typed as production data: in case 2 the three acquisitions deliver plain data, and only the result of merging them is production data. Asking for the narrower class would have missed all three.

### CQ 10: Where is data merged, and out of what?

A merging takes several datasets and produces one. Both ends are reported: isProcessedBy names what goes in, createsProcessedData what comes out, and the assignment names the device doing it. The question matters for provenance. A merged dataset has more than one origin, and a model trained on it inherits every one of them.

**Query** `tests/queries/cq10_merging.rq`

```sparql
PREFIX aias:     <https://w3id.org/aias#>
PREFIX vdi3682:  <https://w3id.org/aias/odp/vdi3682#>
PREFIX iso22989: <https://w3id.org/aias/odp/iso22989#>
SELECT ?merging ?resource
       (GROUP_CONCAT(DISTINCT ?input;  separator=", ") AS ?inputs)
       (GROUP_CONCAT(DISTINCT ?output; separator=", ") AS ?outputs)
WHERE {
  ?merging a iso22989:Merging .
  OPTIONAL { ?input iso22989:isProcessedBy ?merging }
  OPTIONAL { ?merging iso22989:createsProcessedData ?output }
  OPTIONAL { ?merging aias:isAssignedTo/vdi3682:isAssignedTo ?resource }
} GROUP BY ?merging ?resource ORDER BY ?merging
```

### CQ 12: Which data leaves the organisation?

A function running on an external cloud takes its data out of the organisation. The question follows the assignment to that kind of resource and reports what each such function works on. For a plant this is the first question a review asks, and the answer is an argument about the architecture rather than about the technology: moving the training to an internal cloud would empty this table.

**Query** `tests/queries/cq12_data_leaving_the_plant.rq`

```sparql

PREFIX vdi3682:  <https://w3id.org/aias/odp/vdi3682#>

PREFIX rdfs:     <http://www.w3.org/2000/01/rdf-schema#>
```

### CQ 13: How is a component tied to a communication?

Three relations, and the direction is what tells them apart: hasCommunication states a bidirectional use, hasInputCommunication a use as a receiver, hasOutputCommunication a use as a sender. The distinction is what makes a data flow readable. On one fieldbus the motors receive commands and send process data, the position sensor only sends, and the control does both, which no single relation could express.

**Query** `tests/queries/cq13_communication_binding.rq`

```sparql
PREFIX aias:     <https://w3id.org/aias#>
PREFIX iso7498:  <https://w3id.org/aias/odp/iso7498#>
PREFIX rdfs:     <http://www.w3.org/2000/01/rdf-schema#>
SELECT ?component ?componentKind ?use ?communication
WHERE {
  VALUES (?relation ?use) {
    (aias:hasCommunication       "both directions")
    (aias:hasInputCommunication  "receives")
    (aias:hasOutputCommunication "sends")
  }
  ?component ?relation ?communication .
  ?component a ?componentKind . ?componentKind rdfs:subClassOf* aias:Component .
  FILTER NOT EXISTS { ?component a ?n . ?n rdfs:subClassOf+ ?componentKind }
} ORDER BY ?communication ?component
```

## Reading the answers across the three cases

Two questions are worth reading as a row rather than one case at a time.

### cq11, which resource carries which function

| | case 1 | case 2 | case 3 |
|---|---|---|---|
| rows | 12 | 17 | 13 |
| AI functions in the cloud | 5 | 6 | 3 |
| AI functions at the edge | 1 | 0 | 4 |

Case 2 puts everything in the cloud, case 3 splits the work in half. That is
the architectural decision of each case stated as a fact, and it follows from
the application: a wear classification tolerates minutes, a rework has to
finish inside the production cycle of one pane.

### cq12, what leaves the organisation

Case 3 is the shortest answer of the three, with four rows against seven. Only
the training and the test data go to the cloud; the data the inference works on
stays in the cell, because the inference does.

Moving the inference outward would lengthen this answer without changing a
single class of the ontology, which is what makes the question worth asking of
a design rather than of a finished plant.
