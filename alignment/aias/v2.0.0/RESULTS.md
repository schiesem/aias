## 1. The system as a whole

### CQ 01: Which functions, components and relations make up a modelled system?

The entry point. The three main classes after Haberfellner, related to an AI system so that a model has one root.

**Query** `tests/queries/cq01_system_parts.rq`

```sparql
PREFIX aias:     <https://w3id.org/aias#>
PREFIX vdi3682:  <https://w3id.org/aias/odp/vdi3682#>
PREFIX iso7498:  <https://w3id.org/aias/odp/iso7498#>
PREFIX iec60050: <https://w3id.org/aias/odp/iec60050#>
PREFIX iso22989: <https://w3id.org/aias/odp/iso22989#>
PREFIX rdfs:     <http://www.w3.org/2000/01/rdf-schema#>
PREFIX owl:      <http://www.w3.org/2002/07/owl#>
SELECT ?system (COUNT(DISTINCT ?function) AS ?functions)
               (COUNT(DISTINCT ?component) AS ?components)
               (COUNT(DISTINCT ?relation) AS ?relations)
WHERE {
  ?system a iso22989:AISystem .
  OPTIONAL { ?system aias:hasFunction  ?function }
  OPTIONAL { ?system aias:hasComponent ?component }
  OPTIONAL { ?system aias:hasRelation  ?relation }
} GROUP BY ?system ORDER BY ?system
```

**Results**

| Case | system | functions | components | relations |
|---|---|---|---|---|
| tc1_cloud | System | 12 | 9 | 16 |
| tc2_hybrid | System | 11 | 9 | 14 |

**Interpretation.** One system per case, with twelve functions, nine components and sixteen
relations in case 1, and eleven, nine and fourteen in case 2.

The counts are close because the two models describe plants of similar size.
What they do not show is the difference, which the questions below bring out.
This one exists as an entry point rather than as a finding.

operations only? Separates the plant that computes from the plant that produces. The answer is what a deployment decision acts on, and it is the first place the two test cases differ: one names a cloud, the other a cloud and an edge device.

### CQ 09: Does the system design stated for an AI system agree with where its functions actually run?

functions actually run? The design is a claim. The assignments are what it has to bear out. A model claiming Edge while training sits in a cloud is wrong, and nothing in OWL objects to it. The query reports the design beside the resource kinds carrying AI functions, so that a reader can compare the two. Enforcing the agreement belongs to SHACL, which the open points of the catalogue record.

**Query** `tests/queries/cq09_design_against_assignments.rq`

```sparql
PREFIX aias:     <https://w3id.org/aias#>
PREFIX vdi3682:  <https://w3id.org/aias/odp/vdi3682#>
PREFIX iso7498:  <https://w3id.org/aias/odp/iso7498#>
PREFIX iec60050: <https://w3id.org/aias/odp/iec60050#>
PREFIX iso22989: <https://w3id.org/aias/odp/iso22989#>
PREFIX rdfs:     <http://www.w3.org/2000/01/rdf-schema#>
PREFIX owl:      <http://www.w3.org/2002/07/owl#>
SELECT ?system ?design (GROUP_CONCAT(DISTINCT ?rk; separator=", ") AS ?resourceKinds)
WHERE {
  ?system iso22989:hasDesign ?design .
  OPTIONAL {
    ?system aias:hasFunction ?function .
    ?function a ?fk . ?fk rdfs:subClassOf* iso22989:AIFunction .
    ?assignment aias:assignedFunction ?function ; vdi3682:assignedResource ?resource .
    ?resource a ?resourceKind . ?resourceKind rdfs:subClassOf* aias:Resource .
    FILTER NOT EXISTS { ?resource a ?rn . ?rn rdfs:subClassOf+ ?resourceKind .
                        ?rn rdfs:subClassOf* aias:Resource }
    BIND(STRAFTER(STR(?resourceKind), "#") AS ?rk)
  }
} GROUP BY ?system ?design ORDER BY ?system
```

**Results**

| Case | system | design | resourceKinds |
|---|---|---|---|
| tc1_cloud | System | Cloud | Controller, Sensor, ExternalCloud |
| tc2_hybrid | System | Hybrid | Controller, EdgeDevice, Sensor, ExternalCloud |

**Interpretation.** The design a system claims, beside the resource kinds actually carrying its AI
functions.

| Case | claims | AI functions sit on |
|---|---|---|
| 1 | Cloud | controller, sensor, external cloud |
| 2 | Hybrid | controller, **edge device**, sensor, external cloud |

Both are consistent with their claim. Had case 2 claimed `Edge` while training
sits in a cloud, this answer would show the mismatch and nothing in OWL would
object. Enforcing the agreement belongs to SHACL, which the open points record.

The sensors and controllers appear because acquisitions are AI functions in
ISO/IEC 22989, and acquisitions sit on the devices that acquire. That is
correct rather than noise: an acquisition is part of the AI life cycle and runs
where the data arises.

### CQ 12: Which AI functions take part in a control?

Whether an inference feeds a control or only reports is the difference between an assistant and a controller, and it is what a safety review looks at first. Two ways of taking part are reported: being a control, and producing the data a control uses. The second is the indirect case, and it is the one the second test case exhibits.

**Query** `tests/queries/cq12_ai_functions_in_control.rq`

```sparql
PREFIX aias:     <https://w3id.org/aias#>
PREFIX vdi3682:  <https://w3id.org/aias/odp/vdi3682#>
PREFIX iso7498:  <https://w3id.org/aias/odp/iso7498#>

PREFIX owl:      <http://www.w3.org/2002/07/owl#>

WHERE {
  {
    ?function a iso22989:Control ; a ?ck .
    ?ck rdfs:subClassOf* iec60050:Control .
    BIND(?function AS ?control) BIND("is a control" AS ?how)
  } UNION {
    ?control a iso22989:Control ; iso22989:usesData ?data .
    ?function a ?fk . ?fk rdfs:subClassOf* iso22989:AIFunction .

```

**Results**

| Case | function | control | how |
|---|---|---|---|
| tc1_cloud | *(empty)* |  |  |
| tc2_hybrid | Correction | Correction | is a control |
| tc2_hybrid | Inference | Correction | produces what a control uses |

**Interpretation.** Which AI functions take part in a control. Empty on case 1, two rows on case 2.

The two rows report two ways of taking part. The correction **is** a control.

The dissertation this work rebuilds records a rule that fires exactly here,

### CQ 13: Which resource plays which role in a control, and where does it sit in the chain?

the chain? Reached through the inverse relations of the IEC 60050-351 pattern: a physical unit realises a functional unit, that unit is the source or the target of an action line, and the line is part of an action path. The role belongs to the functional unit, and one device may realise several, which the answer reports rather than resolves. A model wanting one role per device would have to assert a cardinality the standard does not state.

**Query** `tests/queries/cq13_resource_control_role.rq`

```sparql
PREFIX aias:     <https://w3id.org/aias#>
PREFIX vdi3682:  <https://w3id.org/aias/odp/vdi3682#>
PREFIX iso7498:  <https://w3id.org/aias/odp/iso7498#>
PREFIX iec60050: <https://w3id.org/aias/odp/iec60050#>
PREFIX iso22989: <https://w3id.org/aias/odp/iso22989#>
PREFIX rdfs:     <http://www.w3.org/2000/01/rdf-schema#>
PREFIX owl:      <http://www.w3.org/2002/07/owl#>
SELECT ?resource ?unit ?line ?pathKind
WHERE {
  ?resource a ?rk . ?rk rdfs:subClassOf* aias:Resource .
  ?resource iec60050:realisesFunctionalUnit ?unit .
  OPTIONAL {
    { ?unit iec60050:isSourceOfActionLine ?line } UNION
    { ?unit iec60050:isTargetOfActionLine ?line }
    OPTIONAL { ?line iec60050:partOfActionPath ?path .
               ?path a ?pathKind .
               FILTER(?pathKind IN (iec60050:OpenActionPath, iec60050:ClosedActionPath)) }
  }
} ORDER BY ?resource ?unit
```

**Results**

| Case | resource | unit | line | pathKind |
|---|---|---|---|---|
| tc1_cloud | *(empty)* |  |  |  |
| tc2_hybrid | ApplicationUnit | FinalElement | L2 | ClosedActionPath |
| tc2_hybrid | ApplicationUnit | FinalElement | L3 | ClosedActionPath |
| tc2_hybrid | RobotControl | ComparingElement | L1 | ClosedActionPath |
| tc2_hybrid | RobotControl | ComparingElement | L4 | ClosedActionPath |
| tc2_hybrid | RobotControl | ControllingElement | L1 | ClosedActionPath |
| tc2_hybrid | RobotControl | ControllingElement | L2 | ClosedActionPath |
| tc2_hybrid | RobotControl | MeasuringElement | L3 | ClosedActionPath |
| tc2_hybrid | RobotControl | MeasuringElement | L4 | ClosedActionPath |

**Interpretation.** Empty on case 1, eight rows on case 2, and the difference is the point of the
question.

The question walks from a resource through the functional units it realises to
the action lines of the control chain and on to the class of the path. Case 1
describes an architecture and leaves its action path unresolved, so the walk
stops at the first step and the answer is empty. That is the correct result for
a model that does not state what it is not asked to state.

Case 2 resolves the control of the plant into the four functional units of
Figure 2 of IEC 60050-351 and the four action lines between them. The answer
then reports the robot control three times, once as comparing element, once as
controlling element and once as measuring element, and the application unit

sitting between two lines, one entering and one leaving.

Three points are readable from the answer and asserted nowhere:

- The device to unit direction. The model states which physical unit realises a
  functional unit, and the answer runs the other way, through the inverse
  relations of the pattern.
- The class of the resource. The model writes `aias:Controller`, and the query
  anchors on `iec60050:PhysicalUnit`. The subclass axiom of the alignment is
  what carries it across.
- The class of the path. `ClosedActionPath` comes out of the chain of lines
  rather than out of the label of the control.

The multiple rows per device are the answer rather than an ambiguity in it. A
device may realise several functional units, the role belongs to the unit, and
ALIGNMENT.md records why the alignment adds no shortcut that would have to
choose one.

PREFIX owl:      <http://www.w3.org/2002/07/owl#>
SELECT ?flow ?source ?target ?communication
WHERE {
  ?flow a ?fk . ?fk rdfs:subClassOf* vdi3682:Flow .
  OPTIONAL { ?flow vdi3682:hasOperatorSource ?source }
  OPTIONAL { ?flow vdi3682:hasOperatorTarget ?target }
  OPTIONAL {
    ?communication a ?ck . ?ck rdfs:subClassOf* iso7498:Association .
    ?communication iso7498:transmits ?pdu .
    ?pdu iso7498:hasUserData ?payload .

  }

## 7. Completeness of a model

### CQ 23: Which resources carry no function at all?

Not necessarily an error. A cabinet or a power supply carries nothing and is still part of the plant. The question reports rather than judges. On both test cases the answer names the resources that exist for a structural reason: an edge device that only bridges to a cloud, and the products, which are components rather than resources and therefore do not appear at all.

**Query** `tests/queries/cq23_idle_resources.rq`

```sparql
PREFIX aias:     <https://w3id.org/aias#>
PREFIX vdi3682:  <https://w3id.org/aias/odp/vdi3682#>
PREFIX iso7498:  <https://w3id.org/aias/odp/iso7498#>
PREFIX iec60050: <https://w3id.org/aias/odp/iec60050#>
PREFIX iso22989: <https://w3id.org/aias/odp/iso22989#>
PREFIX rdfs:     <http://www.w3.org/2000/01/rdf-schema#>
PREFIX owl:      <http://www.w3.org/2002/07/owl#>
SELECT ?resource ?kind
WHERE {
  ?resource a ?kind . ?kind rdfs:subClassOf* aias:Resource .
  FILTER NOT EXISTS { ?resource a ?n . ?n rdfs:subClassOf+ ?kind .
                      ?n rdfs:subClassOf* aias:Resource }
  FILTER NOT EXISTS { ?any vdi3682:assignedResource ?resource }
} ORDER BY ?resource
```

**Results**

| Case | resource | kind |
|---|---|---|
| tc1_cloud | EdgeDevice | EdgeDevice |
| tc2_hybrid | ApplicationUnit | Actuator |

**Interpretation.** Which resources carry no function. One in each case, and neither is an error.

Case 1 names the edge device, which exists only to bridge the machine control
to the cloud. Case 2 names the application unit, which acts on the material
without any function being assigned to it in this model.

Both are legitimate. A cabinet or a power supply carries nothing and is still
part of the plant, and the question reports rather than judges.

### CQ 24: Which AI functions use data that no resource of the plant acquires?

Question 08 of the ISO/IEC 22989 pattern asks which data a function uses, and question 26 which data lacks an acquisition. This one asks whether the acquisition reaches a resource, which neither pattern can answer alone. Data without an origin in the plant is not wrong. It may come from a supplier, a simulation or an earlier project. The question names it so that a reviewer can ask where it did come from.

**Query** `tests/queries/cq24_data_without_plant_origin.rq`

```sparql
PREFIX aias:     <https://w3id.org/aias#>
PREFIX vdi3682:  <https://w3id.org/aias/odp/vdi3682#>
PREFIX iso7498:  <https://w3id.org/aias/odp/iso7498#>
PREFIX iec60050: <https://w3id.org/aias/odp/iec60050#>
PREFIX iso22989: <https://w3id.org/aias/odp/iso22989#>
PREFIX rdfs:     <http://www.w3.org/2000/01/rdf-schema#>
PREFIX owl:      <http://www.w3.org/2002/07/owl#>
SELECT ?function ?data
WHERE {
  ?function iso22989:usesData ?data .
  FILTER NOT EXISTS {
    ?data iso22989:isAcquiredBy ?acq .
    ?assignment aias:assignedFunction ?acq ; vdi3682:assignedResource ?res .
  }
} ORDER BY ?function ?data
```

**Results**

| Case | function | data |
|---|---|---|
| tc1_cloud | *(empty)* |  |
| tc2_hybrid | *(empty)* |  |

**Interpretation.** Empty on both cases. Every dataset an AI function uses traces back to an
acquisition on a resource.

Data without an origin in the plant is not wrong. It may come from a supplier,
a simulation or an earlier project. The question names it so that a reviewer
can ask where it did come from, and an empty answer says there is nothing to
ask about.

### CQ 25: Which parts of a model belong to no subdomain pattern?

What a model states beyond the four standards. A large answer means the standards cover less of the case than intended, which is a finding about the selection rather than about the model. The devices are the expected answer, since aias:Sensor and its siblings come from no standard. Anything else in the answer is worth looking at.

**Query** `tests/queries/cq25_alignment_only_parts.rq`

```sparql
PREFIX aias:     <https://w3id.org/aias#>
PREFIX vdi3682:  <https://w3id.org/aias/odp/vdi3682#>
PREFIX iso7498:  <https://w3id.org/aias/odp/iso7498#>
PREFIX iec60050: <https://w3id.org/aias/odp/iec60050#>
PREFIX iso22989: <https://w3id.org/aias/odp/iso22989#>
PREFIX rdfs:     <http://www.w3.org/2000/01/rdf-schema#>
PREFIX owl:      <http://www.w3.org/2002/07/owl#>
SELECT ?instance ?kind
WHERE {
  ?instance a ?kind .
  FILTER(STRSTARTS(STR(?kind), STR(aias:)))
  FILTER NOT EXISTS {
    ?instance a ?other .
    FILTER(?other != ?kind)
    FILTER(STRSTARTS(STR(?other), "https://w3id.org/aias/odp/"))
  }
} ORDER BY ?kind ?instance
```

**Results**

| Case | instance | kind |
|---|---|---|
| tc1_cloud | Cloud | ExternalCloud |
| tc1_cloud | EdgeDevice | EdgeDevice |
| tc1_cloud | MachineControl | Controller |
| tc1_cloud | MotorControl | Controller |
| tc1_cloud | SensorLeft | Sensor |
| tc1_cloud | SensorRight | Sensor |
| tc2_hybrid | ApplicationUnit | Actuator |
| tc2_hybrid | Camera | Sensor |
| tc2_hybrid | Cloud | ExternalCloud |
| tc2_hybrid | EdgeDevice | EdgeDevice |
| tc2_hybrid | IdReader | Sensor |
| tc2_hybrid | RobotControl | Controller |

**Interpretation.** Six rows in each case, and all of them are devices.

That is the expected answer. `aias:Sensor` and its siblings come from no
standard, so they are the parts of a model belonging to no subdomain pattern.
Anything else appearing here would be worth looking at, since it would mean the
four standards cover less of the case than intended.

The answer is also a measure of how much of a model rests on decisions of this
work rather than on standards. Six of roughly forty individuals per case is a
proportion the accompanying text can state rather than estimate.
